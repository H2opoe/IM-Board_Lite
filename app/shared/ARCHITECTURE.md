# 后端模块职责与修改边界

本文件描述四个正式版共用的依赖方向。平台实现按版本保留；Demo 使用独立展示入口，不接入以下业务链路。

## 调用方向

前端功能 API → Tauri 命令 → 同步／账号／消息领域模块 → 平台连接器 → 桥接执行器 → 原生 CLI。

数据库写入由领域仓库负责。诊断分类只生成事件，诊断仓库负责脱敏、持久化和保留期限。平台模块不应反向调用前端状态或另起同步定时器。

## 已明确的模块边界

| 模块 | 职责 | 保留的接口与约束 |
|---|---|---|
| `bridge_runner/mod.rs` | 请求与结果模型、平台分发、执行编排 | 保留 `BridgeRequest` / `BridgeEnvelope`；命令参数和 JSON 语义由契约测试保护 |
| `bridge_runner/command.rs` | 原生进程创建、UTF-8 环境和 Windows 控制台策略 | 普通 Rust 子模块；不查找 Node，不解释 JS 或 shell 包装器 |
| `runtime/official_cli` | 固定原生产物、校验、暂存、自检、替换和恢复 | 下载清单是版本和哈希的来源；共享缓存由应用持有，账号生命周期不触发卸载；不能绕过自检直接启用下载物 |
| `diagnostics.rs` | 业务失败转换为结构化诊断事件 | 事件生产者只调用现有记录接口，不直接操作诊断表 |
| `diagnostics/bridge_classification.rs` | 平台错误分类及面向用户的说明 | 纯分类函数，不读数据库、不创建进程；各版本按实际平台适配 |
| `diagnostics/ai_classification.rs` | AI 错误分类 | 分类规则共用，避免不同入口产生矛盾状态 |
| `diagnostics/repository.rs` | 元数据白名单、插入、90 天／2000 条保留限制 | 所有诊断写入经过同一脱敏路径；测试使用临时 SQLite |
| `daily_cache/day.rs` | 看板日期与当地清理时刻 | 一次读取当前时间，复用自然日边界；缺失时刻顺延，重复时刻采用首次到达，不执行数据清理 |
| `messages/import_window.rs` | 消息导入的当地日期范围与时间戳边界 | 不依赖同步编排、数据库或平台连接器；消息归一化、历史补读和同步共同使用 |
| `sync/outcome.rs` | 单账号读取结果、部分导入数量和错误汇总 | 不启动进程或写库；保留失败时已导入数量，不能把部分失败标成成功 |
| `sync/orchestrator.rs` | 同步生命周期、阶段推进与取消 | 测试移至 `orchestrator_tests.rs`；调度行为仍由原入口控制 |

拆出测试降低入口文件的阅读成本，不代表业务耦合已全部消除。同步读取、账号绑定状态机和 CSS 覆盖层仍需继续分解和场景验证。

## 新增功能的修改顺序

1. 先确定版本和平台能力，再更新连接器能力声明与领域接口。
2. 在平台适配层实现外部协议；领域层只处理规范化结果。
3. 仓库负责事务、去重和账号隔离；UI 通过既有 API 和同步状态订阅获取结果。
4. 在最近的模块测试边界验证失败、取消和并发行为；前后端字段变化同时更新契约测试。
5. 核对同步清单。公共实现及测试按文件列入；有版本差异的文件登记人工适配依据。

## 后续拆分顺序

先完成 Windows 授权会话的取消安全，再拆同步读取的外部调用与消息入库，最后拆绑定 UI 状态及 CSS。前两项涉及账号和数据边界，应先提供可注入的替身进程／仓库，再迁移代码。CSS 拆分应以主题和窗口尺寸截图验证，不按行数机械分割。

## 账号文件清理

账号路径由 `profile_manager/runtime_paths.rs` 统一校验和计算。账号数据库记录与 `app_meta` 中的待清理相对目录列表在同一事务内提交；`cleanup_queue.rs` 在删除请求和应用启动时重试，完成后删除队列记录。每次重试都核对现存账号和绑定草稿的引用。队列不保存账号配置、凭据或绝对目录。文件清理不能与 SQLite 组成单次事务，因此失败保留队列，重复清理已不存在的目录是安全的。
