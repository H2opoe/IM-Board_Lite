# 官方 CLI 安装与升级

应用执行企业微信、飞书和钉钉的原生 CLI（钉钉使用固定源码适配版），不执行 npm 包里的 JavaScript 入口或安装脚本。

`src-tauri/src/runtime/official_cli/native-artifacts.json` 固定支持版本的下载地址和摘要：npm 包使用官方 registry 的 SHA-512 integrity；飞书原生发行资源使用 GitHub Release asset 的 SHA-256 digest。安装不查询 latest、不解析版本范围，也不展开通用 npm 依赖树。企业微信仅下载根包及当前系统的原生包；飞书的 JavaScript 交互提示库不属于原生执行链路。

支持 macOS arm64/x64 和 Windows x64。其他目标拒绝安装，新增目标必须补充资源、摘要及原生验证。飞书镜像和官方源使用同一固定摘要，镜像返回错误内容不会被接受。下载有连接及总时限，最多 128 MiB；解压在独立暂存目录进行。

每次升级先下载并检查包名、版本、归档边界，再运行原生入口的 `--version` 自检。自检使用独立配置目录和清理后的环境，15 秒超时。自检通过才替换旧目录，并保留 `.平台.previous`；失败或取消会清理本次暂存。安装与临时目录清理共享应用内互斥锁。进程被系统强制终止后的暂存由显式清理操作处理；旧版本备份在下次启用前恢复检查。

## 更新版本

1. 在官方 npm registry 与项目 Release 核对来源、包版本和许可证，保存元数据证据。
2. 同时更新 `OFFICIAL_CLIS` 的兼容版本与固定清单，不使用未经审查的运行时摘要。
3. 在三个目标系统验证 `--version`、绑定、同步、取消、升级失败及旧版本可用性。
4. 运行安装器回归、归档安全测试、Lite 边界与跨版本检查；共享清单同步到四个正式版。Demo 没有 CLI 安装器。

当前清单来源：
- 企业微信：<https://registry.npmjs.org/@wecom/cli/1.3.4> 及对应 `@wecom/cli-*` 的 `1.3.4` 元数据。
- 飞书：<https://registry.npmjs.org/@larksuite/cli/1.0.98>、<https://api.github.com/repos/larksuite/cli/releases/tags/v1.0.98>。
- 钉钉：上游固定提交 `92c4f8c355c749ec470c68f998d862a00d7d1709`，归档、依赖补丁、Go 工具链见 `cli-adapters/dws-isolation/source-lock.json`；现用 `1.0.65-imboard.1`，不再下载旧 npm 产物。

## 共享缓存的生命周期

已校验的 CLI 属于应用级依赖缓存。关闭绑定窗口、删除单个或全部账号不会卸载共享可执行文件，避免影响尚未保存的绑定和在途执行，也避免重新绑定时重复下载。账号自身的数据清理由账号仓库流程负责；失败安装的暂存目录由安装器释放。升级至多保留一份上一版本用于恢复，用户可随应用数据一并清除该缓存。

## Windows 钉钉隔离适配

Windows 钉钉使用内置 1.0.65-imboard.1，来源和补丁见 cli-adapters/dws-isolation。它不通过 npm 更新为全局授权存储版。宿主核验完整 SHA-256 和隔离能力标记，账号凭据由 DPAPI 保存在独立命名空间。旧账号仅迁移应用配置目录里此前保存的加密 token，校验失败则要求重新授权。

## macOS 钉钉安全适配

macOS 两版使用内置 `1.0.65-imboard.1`。每种架构的包保持压缩状态随应用签名与发布，安装时先核验归档 SHA-256，安全解压后再次核验可执行文件。已安装文件和账号配置中的可执行文件都必须匹配当前架构的固定哈希；旧版本会进入准备流程，读取入口不会绕过验证直接执行。原有 macOS 账号 keychain 行为保持不变。

更新 DWS 时，必须重建四个正式版所需产物，执行已锁定依赖和实际二进制的安全扫描，生成依赖／许可证据，并同时更新资源清单、宿主哈希及连接器兼容版本。`scripts/build-dws-isolated.py --target macos` 生成两种 macOS 归档，默认 `--target windows` 生成 Windows 可执行文件；CI 比较重建产物。

## 企业微信自动通讯录读取

保留 1.3.4 的 `auth init` / `auth show` 授权流程。新版 `contact users search` 要求非空关键词，不能替代完整的授权可见通讯录枚举。

`bridge_runner/wecom_read_compat` 使用官方 0.1.9 所定义、已通过现有授权只读验证的读取协议：签名调用 `get_mcp_config`，再通过返回的官方 HTTPS 地址调用 `get_userlist`、`get_msg_chat_list` 和 `get_message`。三个读取命令使用同一协议中的 ID；不安装旧 CLI，不要求用户手填联系人，也不限制为 10 人。通讯录范围由服务端授权决定，不等于整个企业。

适配器只读当前账号目录中的 `credentials.enc`（兼容旧 `bot.enc`）与 `.encryption_key`，不修改授权、不读取全局钥匙串。已有新凭据损坏时不会回退到旧账号。认证 URL、联系人内容、消息内容均不写入错误日志；拒绝重定向和非官方域名。分页重复、格式异常或达到安全上限时明确报错，不把部分结果当成完整同步。读取上限为每个命令 100 页、20,000 条或 32 MiB，网络单次响应上限 8 MiB。

真实账号只验证了通讯录数量；消息读取和分页使用隔离测试数据验证，Windows 实机同步仍需回归。未来若官方撤销该协议，应明确报不支持，不能悄悄退化为仅群聊或手工关键词搜索。

## 企业微信发言人姓名

消息显示优先采用接口返回的姓名；若接口只返回 `userid`，使用同一账号授权可见通讯录的 `userid → name` 映射。未知或不可见成员保留账号标识，不能使用群名或其他账号的姓名冒充发言人。发送者 ID 始终保持原值，以维持消息归属、去重和统计。

映射仅驻留内存，按账号配置、profile、机器人身份和凭据区分，5 分钟有效，最多 32 个账号、序列化映射合计 4 MiB。常规同步的通讯录发现会刷新映射；直接读取消息在未命中缓存时先读取该账号通讯录，不会为每个会话重复查询。同步成功读取通讯录后，只回填该账号历史消息中空白或等于 ID 的占位姓名，不覆盖消息自带的真实姓名，不修改消息内容或身份。

## 飞书排行榜的本人识别

保留单聊“当天双方都发过言”的入榜条件。飞书消息使用真实用户 OpenID，而非 `me/self/我` 占位值；两个榜单共用账号作用域内的本人判断。已有绑定的 `accountIdentity.userId` 可直接用于识别，成功的 CLI 授权预检则从 `identities.user.openId` 提供当前用户身份，不能使用机器人或应用 ID。

预检已经是每次消息检索的必要步骤，不新增 CLI 调用。成功检索后，将确认的用户 OpenID 保存到对应飞书 profile 的 `feishuSelfOpenId`，供现有消息统计使用。发送者 ID 和消息内容保持原值，不需要重导历史消息，也不放宽双向聊天规则。单向来信、只有本人发言以及不同账号各自只有一侧消息，仍不能凑成双向聊天。

## 钉钉排行榜与群聊标记

钉钉也保留“双方当天都发过言”的单聊筛选条件。当前账号通过隔离 CLI 的 `contact user get-self` 确认，按已绑定企业筛选本人记录，仅从本人及本人用户模型提取消息 ID 别名，不能递归收集主管、部门或其他账号的 ID。确认的别名保存在对应 profile 的 `dingtalkSelfIds`，排行榜按同一 profile 匹配；不会按姓名猜测本人。身份查询不可用时明确告警，已有消息读取仍保留。

消息窗口导入采用读取结果中的 `isGroup`，而非固定写入单聊。重复导入更新已有消息的群聊元数据，消息 ID、内容和条数保持不变。真实群聊沿用原有群聊发言排行规则；真实单聊仍必须双方当天都发过言才能入榜。


钉钉若已返回明确的 openDingTalkId，直接使用已确认的身份；否则用本人明确的 userId 调用 `contact user get --ids <当前用户ID>` 补全消息 ID，环境、租户、缓存和钥匙串与原查询完全相同。不按姓名搜索，也不接受其他用户的结果。补全失败只保留已确认的标识并告警，不输出原始联系人响应。

钉钉未授权的“resolve access token + secure data file + .data 不存在”复用现有 `DINGTALK_NOT_AUTHENTICATED` 和通用未完成授权提示。普通内部错误、权限拒绝和解密失败不套用重新授权提示；终端名称继续按 macOS/Windows 平台生成。飞书仍保留应用配置及用户授权两阶段的专用提示。

钉钉本人消息身份补全：精确用户详情查询成功但仅返回组织 ID 时，继续以已确认的本人用户 ID 执行 `contact user search --query`；只有结果用户 ID 完全一致且包含明确 OpenID 才视为完成。不按姓名猜测，不接受其他用户或歧义结果。所有补全查询保留相同的账号隔离环境与 Windows DPAPI 包装。

Windows 钉钉绑定依次显示扫码登录、消息权限授权、身份核验三个阶段。权限授予保留 `chat.message:list` 的 permanent 范围，独立进程最多等待 180 秒；超时终止并确认其退出后保留已登录凭据。账号锁采用立即检测，保存配置遇到正在进行的终端操作时返回可重试提示，不排队等待五分钟。Windows 凭据持久化在账号专属 DPAPI 加密注册表空间，不能用 `.data` 文件存在与否判断登录成功。

Windows 发布资源只从当前源码和已验证运行时清单组装，不继承历史便携模板或旧构建输出。专用读取器仅包含运行所需模块与许可，不携带开发诊断、截图、npm 外壳、测试目录或用户配置。
