# 读取结果判定

`read-result-contract.json` 是同步与测试读取的公共规则和提示语来源。Rust 的
`bridge_runner/read_result.rs` 与前端 `api/readResult.ts` 共同使用这份契约，
并用 `read-result-fixtures.json` 验证相同的空集合、失败、分页和异常结构。

- 成功读取必须返回明确的集合。空集合是正常结果，不能据此推断未登录或无权限。
- 缺字段、无效 JSON 或无效字段类型不能降为零条成功。
- 明确的授权/API 错误优先使用平台错误码和提示；通用层不从消息正文推断权限。
- 未完成分页、截断、解密失败或其他失败账本不能作为完整读取成功。
- 历史读取若提供可保留的记录及明确的失败账本，同步保留已读记录，同时记录失败，
  不推进成功检查点；测试读取仍报告不完整。零条失败结果直接报错。
- 后台同步不因零条结果额外提示。用户主动测试读取时，各平台使用同一句空结果成功提示。

各平台适配只保留协议差异：本机读取器的登录/解密错误与分片记录；企业接口的
业务错误和游标；飞书的授权错误和搜索会话投影；钉钉固定 CLI 的 complete 证明
及已验证的省略空集合响应。新增条件或通用提示时先修改公共契约与公共样例。

Demo 不读取真实账号；Lite 不包含个人平台实现。公共契约及样例只使用中立字段。
